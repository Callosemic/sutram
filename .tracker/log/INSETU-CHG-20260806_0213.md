## Description
This update introduces core presentation primitives for loading indicators and empty states, modernizes state-bound form inputs to use custom Web Components, and prevents double-firing of click events on toggle inputs.

### Key Changes Implemented
* **yenVUI Presentation Chassis (`yenvui/js/spinner.js`, `yenvui/js/empty-state.js`)**:
  * Built `YenvuiSpinner` (`<yenvui-spinner>`) to render an animated loading indicator with standard intent styling and custom label slots.
  * Built `YenvuiEmptyState` (`<yenvui-empty-state>`) to display fallback states with icon and text feedback.
* **Sutram Wrapper Primitives (`sutram/js/primitives.js`)**:
  * Created `SutramSpinner` (`<sutram-spinner>`) and `SutramEmptyState` (`<sutram-empty-state>`) Web Components forwarding options to the underlying yenVUI presentation chassis.
* **Store Input Binding Modernization (`sutram/js/sdk.js`)**:
  * Upgraded `bindStoreInput` helper to delegate to `sutram-input`, `sutram-select`, `sutram-textarea`, and `sutram-toggle` components instead of raw HTML5 inputs.
  * Extended options with `label` and `inline` layout flags and updated event listeners to consume `@sutram-input-changed` custom events.
* **Toggle Event Mitigation (`sutram/js/inputs.js`)**:
  * Updated `SutramToggle._onToggle` to consume the native event `e` and invoke `preventDefault()`, resolving native `<label>` click event double-firing.
* **Architecture Index Update (`CODE_INDEX.md`)**:
  * Added entries for `yenvui/js/spinner.js` and `yenvui/js/empty-state.js`.

## Notes / Execution Log
All updates strictly maintain zero-bundler ES module compatibility, declarative UDF state isolation, and lifecycle safety.
